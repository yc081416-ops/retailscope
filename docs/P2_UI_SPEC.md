# P2 交互与界面规范

P0/P1已验收，P2仅增加只读分析界面，不重建仓库或修改统计模型。入口为`app/Home.py`，六个页面由`st.navigation`管理。

## 布局与视觉

- 浅色背景、蓝色主色#2457D6，青色辅助色#148A9B；橙色仅用于不完整月份标记。
- 常见桌面1440×1000、1280×900验证；侧栏固定导航，内容宽度上限1560px，指标卡与图表边框保持一致。
- 使用系统中文字体和统一Plotly白底模板；坐标轴13px，热力图单元10px；所有金额标明BRL。
- 金额卡片可换行且采用不等宽列，避免长金额被省略；日期、州、类目控件置于页面顶部。
- 不使用大面积渐变或装饰动画。图表提供悬停、缩放、图像下载；结果表提供CSV导出。

## 页面与范围

| 页面 | 路径 | 图表及数据 | 筛选规则 |
|---|---|---|---|
| 经营总览 | `/` | 商品金额、有效订单、唯一用户、客单价；月度商品金额与订单、全状态分布、州贡献 | 购买日期、客户州；同页全部组件共用范围，状态分布另外包含全部状态 |
| 用户价值分析 | `/users` | 六个非空RFM层、人数/贡献、频次、复购率、Cohort热力图、月度新增用户 | 固定P1全样本，显式说明不联动其他页面 |
| 商品与品类分析 | `/products` | 金额/件数/订单/运费，TOP10金额及贡献、帕累托、月度趋势、件数/订单对比 | 日期、州、类目；只统计选中类目的商品行 |
| 履约与评价分析 | `/delivery` | 配送天数、逾期率、评价均分；5天分箱、最新评分分布、州表现、逾期/评价比较 | 日期、州、类目；类目条件是订单包含任一选中类目，每订单仅一次 |
| 经营发现 | `/findings` | P1已验收的8项描述性事实，逐项标注来源和范围 | 固定P1全样本；不引入P3诊断或预测 |
| 数据质量中心 | `/quality` | 九表实时行数；P0缺失/重复/关联快照；当前mart异常；P1构建与对账记录 | 全局数据，不与局部筛选联动；区分实时结果与历史审计快照 |

总览3张、用户5张、商品5张、履约4张，共17张业务图表。事实与质量页以可复核文本、结果表和下载为主，不人为添加无意义图形。

## 日期、金额与分母

- 首次打开显示全数据集购买日范围，取自mart.dim_date；所有P1有效购买订单均被覆盖。日期控件包含首尾日，SQL使用`[start,end+1day)`。
- 默认全状态日期为2016-09-04至2018-10-17；有效购买实际范围为2016-09-15至2018-08-29。总览月度图以有效购买观察范围为上限，避免把样本结束后无数据误画成经营归零。
- 月度图保留P1空月份；首尾不完整月、选择的局部月份标记为橙色。P2不计算月增长率。
- 商品金额来自price；运费和支付金额分开显示。没有成本与完整退款数据，不能称为净利润或财务确认收入。
- 商品页类目金额、件数可加，类目内去重订单数跨类目不可直接相加；页面同时显示真实去重订单KPI。
- 配送时长、逾期和评价分母遵守P1：无效配送日期排除该统计分母，交易保留；评价均分订单等权，评分分布一订单取最新评分。

## RFM 与 Cohort

- 完全查询P1视图，不在页面重算或改分组；不存在局部筛选引起的虚假联动。
- Frequency分位点大量重复，明确说明评分2–4空档是源数据分布所致。六个非空层与P1一致，零人数“数据待核对”不混入六层。
- Cohort不可观察单元保持NULL，显示为空白，导出为NA；完整观测无回购才是0%。首cohort左截断有说明。
- 热力图色阶在2%封顶以显示小比例差异，图中明确标注；单元文字和悬停显示实际值，M0可显示100%。类别轴保证每个cohort月份标签可见。

## 数据访问、缓存与故障

- SQLAlchemy连接池统一管理，PostgreSQL会话只读；连接超时5秒、语句超时20秒。
- 查询名称固定白名单；日期、州及类目全部绑定参数，列表参数声明String类型，空选择表示全部。没有任意SQL输入框。
- `scoped_orders`保证订单粒度，类目订单筛选使用EXISTS；`scoped_items`只连接唯一商品维表，不直接连接支付/评价/原始地理明细。
- 查询结果缓存120秒、最多128项，筛选对象作为缓存键；侧栏可主动刷新。P1仓库刷新后可清缓存或等待TTL，不显示伪造的实时性。
- 日期只选择一端时提示补全；无匹配记录时提示调整或清空筛选。数据库不可用时显示中文错误及“重新连接”，不显示连接串、密码或原始异常。
- 查询日志仅记录白名单指标名、行数、耗时与异常类型，保存`reports/p2/queries.log`。

## 导出

每个结果表的CSV直接来自生成该组件的同一个DataFrame；UTF-8 BOM编码方便Windows Excel，金额保留数据库数值精度，NULL导出NA。筛选标签在页面顶部，导出文件使用明确的指标名。浏览器下载还会与相同筛选SQL结果逐字段对账。

## 本地启动

```powershell
.\.venv\Scripts\python.exe -m streamlit run app/Home.py
```

打开`http://127.0.0.1:8501`。需先启动现有Docker数据库，保留原`.env`。不运行P0/P1重建脚本。自动测试使用`python -m pytest -q`，验收日志应写入`reports/p2/`以保留P0/P1证据。
