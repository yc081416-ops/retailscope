# P3 分析方法、口径与解释边界

## 数据与分析单位

数据来自Olist / Kaggle公开历史样本，CC BY-NC-SA 4.0。P3只读既有PostgreSQL mart，不执行DDL、原始数据清洗或P1重建。有效订单沿用P1的delivered及有效购买时间；购买期为2016-09-15至2018-08-29。金额单位BRL，商品金额、运费、支付金额独立，不代表财务确认收入或利润。

查询在单个REPEATABLE READ只读事务执行，SQL位于`sql/p3/`；输入行数、查询文件SHA-256、输入CSV SHA-256、生成时间和配置记录在`reports/p3/analysis.json`。分析计算单独运行，不在页面点击时重采样。

| 查询标识 | 文件 | 粒度/作用 |
|---|---|---|
| P3_CONTEXT | context.sql | P1边界、RFM基准日及完整月观察终点 |
| P3_KPIS | kpis.sql | P1全样本经营指标，一行 |
| P3_MONTHLY | monthly.sql | 月份，保留P1完整月标记 |
| P3_CATEGORIES | categories.sql | 类目金额、件数、类目内去重订单 |
| P3_REGIONS | regions.sql | 客户州，独立配送和逾期分母 |
| P3_ASSOCIATION | association_orders.sql | 每有效订单一行，保留缺失以核对排除人数 |
| P3_RFM_USERS | rfm_users.sql | 每唯一用户一行，复用P1分层与观测首购月 |
| P3_COHORT | cohort.sql | 首购月×月龄，保留不可观察NULL |

## 完整月份及可比增长

完整目标月区间沿用P1：`[2016-10-01,2018-08-01)`。不完整月仍保留在输出表，但不计算该月环比、同比或异常提示。

- 环比仅比较相邻日历月；同比仅比较相隔12个月的相同日历月。两端必须完整且各至少100单，基期金额必须为正。
- 增长率为当期/基期−1，金额使用Decimal计算后才转换为展示比率。不存在基期、基期为零或样本不足时结果为NULL，并记录原因。
- 100单是本阶段事先固定的描述性稳定性门槛，不是显著性标准，也不能证明源数据覆盖完整。源样本早期完整日历月份可能无记录或极少记录，不应把它们直接解释为平台经营归零或爆发式增长。
- 未做季节调整、渠道/产品结构控制或预测；同比数据很少，不能据此外推未来。

## 中位数与MAD异常回顾提示

对合格环比使用`log(当月/上月)`，降低规模增长对水平值异常筛查的影响。分别对商品金额与订单数计算：

`modified_z = 0.6744897502 × (对数环比−全部合格对数环比的中位数) / MAD`

MAD为绝对离差的中位数。至少12个合格相邻月份对且MAD>1e-12才启用；`abs(modified_z)>3.5`仅标记为需要复核的月份。MAD为零、样本不足或增长基线不合格时不强行判定正常/异常。参考[NIST异常值筛查说明](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35h.htm)。

该方法使用整段历史作回顾性参照，未控制季节性或多重比较，不是前向报警模型或正式显著性检验。异常不等于错误数据，程序不会删除记录；不能借此声称未来经营走势。

## 类目、地区与集中度

- 类目份额=`该类目有效商品金额/全部有效商品金额`，unknown类目保留；TOP5/TOP10贡献按金额降序累计。
- HHI=`Σ份额²`，原尺度0–1，同时给出×10000的表示。它只描述该数据样本的类目金额结构，不套用市场反垄断阈值。
- 帕累托给出覆盖80%金额所需类目数。金额及商品件数可相加；同一订单可能跨类目，类目内去重订单不能直接相加作为总订单。
- 类目或州少于100单时标记小样本；不把原始均值的名次当作稳定绩效结论。地区配送均值、有效配送n、逾期n及订单规模并列显示。
- 州逾期比例附Wilson工作独立近似95%区间，n<30不计算；该辅助区间未处理同用户相关，不作地区显著性排名。地区距离、类目、时间、商户等差异可能混杂。

## 配送与评价关联

先从P1有效订单表取一订单一行。仅在is_late、review_mean、latest_review_score、customer_unique_id均非空时进入两组对照，分别记录缺失项及排除总人数。缺失项可能重叠，不能把逐项缺失简单相加。P1逾期定义为实际送达日>预计日；同日不算逾期。缺失或异常配送日期沿用P1分母规则。

评价均分使用订单内全部评价的平均，再对订单等权；低评分比例按每订单最新评分≤2计算。两种评分统计口径明确区分。两组给出实际订单数、用户数、均分、低评分人数和比例；差值方向统一为**逾期−未逾期**，比例差以百分点解释。

### 使用条件检查

程序检查订单主键唯一、有效评分处于1–5，记录两组是否各≥30、唯一用户数、最大用户聚类订单数、同用户同时进入两组的数量及有效重采样数。评分虽为有界有序量，均值仅作为常见描述指标；实际大样本可提供渐近近似，但不能把序数分差解释为精确的满意度效用差。

### 主95%区间：用户整群bootstrap

按customer_unique_id汇总每组订单数、评分和、低评分数；以用户为单位有放回重抽样，将一个用户的全部订单和两组贡献一起抽取，再重新计算订单加权均分差及低评分比例差。这样保留用户内相关及同用户跨组关系，**不是把订单均值改为用户等权均值**。

固定种子20261113，2000次重采样，取2.5%和97.5%百分位作为95%区间，分批计算限制内存。两组至少30单且至少30个用户才提供区间；有效重采样不足99%则标记不可计算。方法流程参考[SciPy bootstrap官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)，本项目显式实现用户整群统计量。

区间条件于这份历史样本，并依赖用户聚类之间近似独立；它不保证Olist样本对全部电商订单有代表性，也未处理同商户、线路、月份等跨用户相关。百分位bootstrap有有限重采样误差，不把四位小数视为真实精度承诺。

### 辅助区间与独立对账

- 评分均分差：Welch不等方差t区间，标准误为`√(s1²/n1+s0²/n0)`，自由度采用Welch–Satterthwaite。使用原订单数组的`scipy.stats.ttest_ind(equal_var=False).confidence_interval()`独立核对摘要公式。参考[SciPy Welch检验文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ttest_ind.html)。
- 两组低评分比例：Wilson单比例区间；差值使用Newcombe方法10的Wilson几何组合。Wilson闭式计算再用二项score统计量的数值求根独立核对，包括零成功和全成功边界。
- 上述辅助区间以订单工作独立为近似，不能替代主用户聚类区间。n<30不计算推断区间；无样本为NULL，不填0。
- 用户bootstrap在可手算测试数据上，使用同一抽样索引直接展开用户的全部订单逐次复算，与汇总统计量方法核对；实际数据重复运行相同种子产生相同区间。

不以p值作业务判断，也不将观察到的评分差异表述为延迟的因果效应。地区/品类/商户/月份、客户预期、评价缺失、选择进入delivered样本等都可能影响结果。

## 用户结构和Cohort

完全复用P1的RFM评分与分层。分别汇总各层人数、占比和商品金额贡献；一次购买与复购组按有效订单次数划分。复购组累计金额更高部分由分组定义决定，不能当作召回措施的效果。

观测首购月到RFM基准日的天数仅为观察机会代理，可能比实际进入时间多最多约一个月；数据开始前的购买未知。比较组的观察机会分布并明确异质性，不作“长期流失”判断。

保留P1的Cohort NULL；仅对次月目标月完整且cohort非左截断的分组，将次月活跃人数之和/首购人数之和作为加权M1描述值。它不是全部cohort的简单平均，也不是连续订阅留存或因果指标。

## 发现、建议与复现

每条发现包含唯一ID、代码生成的实际结果、SQL标识、观察范围、样本与分母、统计方法、局限和待验证建议。界面不手写业务数值。建议统一表述为需进一步核验或前瞻性对照试验验证，不声称已改善增长。

`python scripts/run_p3.py`生成`reports/p3/analysis.json`、SQL结果CSV、月度诊断CSV及`docs/P3_BUSINESS_REPORT.md`；页面Markdown下载调用同一报告函数，因此与生成文件一致。`tests/test_p3.py`包含独立统计、口径、缺失/空样本、不完整月份与报告一致性测试。运行日志及截图在P3目录保存，P0/P1原数据与验收报告保持不变。
