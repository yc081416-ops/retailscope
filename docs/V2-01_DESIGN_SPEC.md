# RetailScope V2-01 统一设计规范

本阶段仅实现经营总览。沿用真实SQL与P1指标，旧版Streamlit独立保留。以简洁导航、清楚的指标层级和紧凑分析工作流体现专业BI质感，不复制任何参考产品界面。

## 设计变量

| 用途 | 规范 |
|---|---|
| 页面/导航背景 | #FFFFFF / #FAFAFB |
| 主文字/次文字 | #202327 / #626771；次级注释最低11px，主要文字不以低透明度表现 |
| 边界/浅背景 | #E6E7EB / #F6F6F8；1px边框，减少阴影 |
| 主操作/金额系列 | #5B50C9 / #7065D8；低饱和紫，避免蓝色背景堆叠 |
| 订单系列 | #3F8D86；金额与订单共用月份但使用上下两个坐标系 |
| 非完整观察月 | 浅紫柱 #B6AFDE、琥珀点 #B07A27；配文字说明，不只靠颜色传达 |
| 字体 | 本地Inter（若存在）、Segoe UI、Microsoft YaHei、sans-serif；不请求外部字体 |
| 字号 | 页面标题27px；KPI 27px（1280宽为24px）；区块13–15px；控件/辅助11–12px；数字tabular-nums |
| 间距 | 4/8/12/16/20/24/32px为主要节奏；导航196px，1280宽收至180px；主区左右26–34px |
| 圆角 | 控件6px、区块8–9px、工作区标识7px；不使用大面积渐变、玻璃和装饰动画 |

原生日期输入由系统/浏览器提供，展示格式可随系统区域设置变化；API始终使用ISO日期。可访问名称、错误提示和交互正文使用中文。

## 信息组织

1. 固定窄侧栏只有总览、当前页锚点、经营发现入口及明确标注的旧版链接。没有其他五个新版页面或无效占位链接。
2. 顶部轻量面包屑与历史样本标识；标题下说明Olist来源和有效购买历史范围。
3. 一行全局筛选：起止日期、客户州、应用、重置。修改后标“更改待应用”，应用前不悄悄切换KPI；导出读取已应用范围。
4. 四项KPI放在统一边框区，用轻分隔线控制密度。金额显示BRL，订单/用户单位清楚；运费、有效订单定义和非财务收入解释单列。
5. 主要趋势在首屏：金额柱图与订单折线图上下对齐，所有纵轴从0开始；不将不完整月份用于增长计算。当前总览没有额外增长或预测算法。
6. 第二层为全状态订单横条与州贡献排行。状态图分母为同筛选全状态订单；贡献分母为同筛选有效商品金额。全部27州可展开，表格内数字右对齐。
7. 底部经营发现入口打开已验收P3快照，明确固定全样本、不随局部筛选；导出区提供四种结果CSV，包含筛选列。

## 图表与组件

- Apache ECharts使用SVG渲染、统一轴色/字体/网格与悬停提示，使用ResizeObserver适配容器；真实数据只来自API。
- 金额图例包含BRL，订单包含单；坐标使用k/m紧凑单位，悬停显示精确金额和订单数。排名表以BRL列头明确单位。
- shadcn/ui由官方CLI生成Button、Badge、Dialog，使用本地cn与Radix组件。没有引入付费模板。
- 图表区域提供可访问名称，控件具有标签；焦点边框可见；支持键盘、Esc关闭对话框。遵循系统减少动态效果设置，图表关闭过渡动画。
- 加载状态只延迟真实请求，不显示伪造KPI；空结果显示0和不可计算的“—”；失败时移除旧KPI，显示中文重连提示，不展示连接串。
