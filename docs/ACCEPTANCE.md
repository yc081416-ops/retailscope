# RetailScope 阶段验收标准

## P0：数据和环境（目标第 1–2 天）
- Docker PostgreSQL 服务可连接；README 提供 Windows PowerShell、macOS/Linux 命令。
- 识别九份指定 CSV；缺少文件时明确报错并列出缺失文件；绝不生成假订单掩盖缺失。
- 可一条命令导入；处理空值/日期/金额类型；原始数据不会被提交到 Git；日志打印每表实际行数。
- `pytest -q` 基础用例通过；Codex 给出真实命令输出。

## P1：SQL 数据仓库（目标第 3–5 天）
- raw/core/mart 分层落地；带数据字典、可重复运行。
- `mart.order_wide` 严格一单一行；每笔订单商品金额和明细求和一致。
- ETL 重跑不增加同批次订单、商品明细行数。
- customer_id/customer_unique_id 口径正确；payments/reviews 多对多膨胀测试通过。
- 全局 SQL 汇总与独立 Pandas 校验的金额、订单数、用户数一致（金额精确到分或记录舍入差异）。

## P2：业务分析（目标第 6–8 天）
- 6 个页面可访问；指标、趋势、RFM、cohort、履约与质量模块均基于数据库数据。
- 时间和州筛选影响相关 KPI 与图表；无数据范围友好提示。
- 6 个页面均有至少 1 项真实 SQL 结果；不少于 12 张有效图表/指标可视组件（不为了数量堆图）。
- Cohort 未观察月份显示空白，RFM 快照日和分群规则可追溯。

## P3：经营诊断与报告（目标第 9–10 天）
- 至少 5 项可复核的真实业务发现；附查询、期间、样本量、量化证据与局限。
- 指标异常采用明示的规则/阈值，不能凭 AI 编造原因或增长。
- 图表至少支持 CSV 导出，README 有真实截图、可重复运行的报告生成步骤。

## P4：工程化与演示（目标第 11–12 天）
- 一键启动说明清晰；pytest 用例全部通过；基础 smoke test 通过。
- `.env.example` 齐全，无凭据泄漏、原始数据入库提交问题。
- 演示脚本：3 分钟展示数据接入、经营总览、用户分层、履约分析、经营结论、质量校验。
- Codex 最终报告包含真实记录数、核心指标值、单元测试数量、主要耗时/瓶颈、已知问题。不可凭空填数字。

## 面试“可解释性”验收
候选人本人能在不看提示情况下回答：为何分层建表？为何不能直接 JOIN payments？为何用 customer_unique_id？GMV 与支付金额不同在哪里？RFM 与 cohort 各回答什么问题？如何判断业务建议可信？SQL 与 Pandas 如何交叉验证？
